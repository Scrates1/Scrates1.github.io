## 第二轮：独立审阅后的修正（同日）

请一位不参与写作的审阅者按“静态分析专业读者 + 初学者”双视角只读审稿，发现并已修正：

- **技术错误**：原第 5 节用静态方法 `fill(h, v) { h.set(v); }` 转发，并声称 1-对象敏感能分开两次 set。实际上 fill 没有接收者，对象敏感让静态方法沿用调用者上下文，两次 fill 只有一份，`pts(v)` 在 fill 的形参上已合流，再按接收者拆 set 也无济于事。改为经实例方法 `init(v) { this.set(v); }` 转发：1-调用点下 set 只有一个调用点而合流（k=2 才分开），1-对象敏感经 `init[o4]`→`set[o4]` 分开。静态转发的合流情形保留为反例，并引出 hybrid context-sensitivity（Kastrinis 与 Smaragdakis，PLDI 2013）。对照表、正文与本篇要点三处同步改正。
- **伪代码与表格不一致**：原伪代码在初始化时对 copy 边“加边并立即传播”，会使 `pts(b)` 在步骤 0 就得到 o1，与表格把它记在步骤 1 矛盾；循环体顺序也与表格步骤 1 的“先 copy 后 store”相反。改为初始化只记录 copy 边、循环体先沿已有边传播再处理 store/load，表格工作列表顺序 `[t1, b, o1.f]` 由此得到。`check_series.py` 的模拟按同一顺序产生同一轨迹。
- **分配点编号**：原 o5 在第 5、6 节重复使用，o2 缺号。统一为 o1（alias）、o2（separate）、o3（factory）、o4/o5（set 例子）、o6（open）；图 2 重渲染。
- **CFL 表述倒置**：原文“`x.f=…` 与 `…=y.f` 匹配就意味着 x、y 可能别名”。改为：x、y 可能别名时两者构成一对匹配括号，值由此流动；基对象是否别名本身是另一个查询。并补上“两种括号同时精确匹配不可判定、只能近似一种”一句，使 07 第 8 节对本篇的前向引用成立。
- 复杂度：n 同时用作节点名与规模参数，改为规模参数 N 并定义为约束图节点数（含字段位置），注明 `O(N³)` 以差分传播为前提。
- 其余定点修正：06 第 3 节列了三种建图方式而非两种；“第 3—6 节的四个例子”改为“3.1、3.2、4、6 节”，注明 set 例子不在示例中；补 k-CFA、RTA、field-insensitive/field-based、demand-driven 的英文与一句话解释，补堆抽象定义，Boomerang/FlowDroid 首次出现给身份；补调用点敏感与 on-the-fly 调用图的直白说法；交代 Jimple 中 `$stack4` 共用临时变量导致的合流及示例为何只打印源码局部变量；两个长段各拆为三段；删一处写作安排句；本篇要点合并为五条。
