[IFDS](07-ifds.md)计算事实能否沿匹配路径到达。如果还要得到变量的数值，就需要描述值在传播中如何变化。IDE（Interprocedural Distributive Environments）在事实关系上附加值变换，用环境记录各事实的抽象值。

## 1. 让事实携带值

下面使用数学整数的伪代码，不涉及机器整数溢出：

```text
calc(p):
    a = p + 2
    b = a * 5
    return b

u = calc(1)    // 调用 A
v = calc(4)    // 调用 B
```

两次调用分别得到 u=15、v=30。calc 的计算过程相同，可以先汇总为一个变换，再分别代入实参。

在方法内部选择有限事实域 `D={p,a,b,ret}`。**环境** `ρ:D→L` 将每个事实映射到抽象值；例如 `ρ(p)=1`。L 包含 `⊥`、每个整数常量及 `⊤`，沿用 `⊥ ⊑ c ⊑ ⊤` 的顺序。

IDE 要求环境变换对合并满足分配律，并满足收敛条件（跳转函数不能无限次变化，第 4 节说明）；边函数要支持有效的求值、组合、合并和等价判定。以适当的两元素值编码事实的存在性，可以将 IFDS 表示为 IDE 的特例。[IDE 原始论文及作者摘要](https://research.cs.wisc.edu/wpis/abstracts/tcs96b.abs.html)

## 2. 事实依赖与边函数

每条事实边上附加的值变换叫**边函数（edge function）**，第 5 节给正式定义；先看它在 calc 里长什么样：

| 语句 | 事实依赖 | 边函数 | 输入为 1 时的过程 |
| :--- | :--- | :--- | :--- |
| `a=p+2` | `p→a` | `f(t)=t+2` | a=3 |
| `b=a*5` | `a→b` | `g(t)=5t` | b=15 |
| `return b` | `b→ret` | `id(t)=t` | 返回 15 |

表中省略了其他未修改事实的恒等边。赋值覆盖左侧旧值，因此要删除左侧的旧值边。

`p→a` 表示 a 依赖 p，`f(t)=t+2` 则计算值的变化。也可写成 `λt.t+2`，读作“将 t 映射到 t 加二的函数”；小写 λ 是匿名函数记号，大写 Λ 则是 IFDS 的辅助事实。

直白地说，IFDS 的边只回答“a 是否因为 p 而存在”，IDE 在同一条边上多贴一张纸条，写着“a 的值等于 p 的值加 2”。传播时不带具体数字，只带纸条；数字到最后才代进去。

## 3. 底值、未知值与常量生成

将算术函数扩展到未知与底值，规则如下：

| 函数 | 输入 `⊥` | 输入常量 c | 输入 `⊤` |
| :--- | :--- | :--- | :--- |
| 恒等 | `⊥` | c | `⊤` |
| 加 2 | `⊥` | c+2 | `⊤` |
| 乘 5 | `⊥` | 5c | `⊤` |
| 常量产生 k | `⊥` | k | k |

底值表示没有有效贡献，不能通过普通事实边凭空产生值。常量赋值 `a=1` 由辅助事实 Λ 到 a 的边产生。Λ 需要携带一个非底的值，才能让“常量产生 k”这一行的函数有东西可输入；本篇把这个值写作 `★`——它不是任何程序常量，只是一个占位记号，“常量产生 k”把它当作表中的非底输入，看到它就产生 k。Λ 自身沿辅助恒等边保留，`★` 永远不变。

“加 2”和数学整数上的“乘 5”都保持不同常量不同，因此对单常量域的 Join 分配：两个不同常量先合成未知，或分别变换再合成未知，结果一致。

截断除法可能把两个不同常量映射到同一个常量，Java 的有限位宽也会改变某些运算的性质。因此，每种抽象变换都需要检查 IDE 的条件；无法精确表示的操作可采用满足条件的保守近似。

## 4. 同一路径组合，多条路径合并

### 顺序执行：函数组合

先 f 后 g，写作 `g∘f`，读作“g 复合 f”：

```text
j(t) = g(f(t)) = 5(t+2)
j(1) = 15
j(4) = 30
```

组合顺序很重要。`f(g(t))=5t+2` 是先乘五后加二，已经换成另一段程序。

### 分支汇合：逐点合并

如果另一条路径先加 4 再乘 5，那么有 `j₁(t)=5(t+2)`、`j₂(t)=5(t+4)`。汇总函数定义为：

```text
(j₁ ⊔ j₂)(t) = j₁(t) ⊔ j₂(t)
```

代入 t=1，两个结果为 15、25，合并为未知。两条路径若都算出 15，就保留 15。

两函数可能仅在某些输入上相等，合并结果就未必能写成一个线性公式。因此，函数表示要对组合与合并封闭，支持等价判定，并满足收敛要求。这些条件需要对函数族单独检查，仅有值格的有限高度还不够。

本篇实际使用的函数族是：一元线性函数 `t↦a·t+b`（含恒等 `a=1,b=0` 与“常量产生 k”即 `a=0,b=k`），加上把一切映到 `⊥` 的底函数和把一切映到 `⊤` 的顶函数。两个线性函数的组合仍是线性函数（系数相乘、常数项代入）；两个系数不同的线性函数逐点合并，本篇直接取顶函数作保守表示；等价判定只需比较系数。这样第 6 节“条目改变才继续调度”就有了判据。原论文的**线性常量传播（linear constant propagation）**采用的正是这一族，完整表示见[原论文](https://research.cs.wisc.edu/wpis/papers/tcs96b.pdf)。

## 5. 从边函数到跳转函数

**边函数（edge function）**通常表示一次事实边上的值变换；**跳转函数（jump function）**汇总当前过程入口到某个目标事实的传播效果。两者的区别是“一步”和“从门口到这里”：边函数是单条语句的一步算式，跳转函数是把入口到当前位置沿途所有边函数组合、再把多条路径合并后得到的那一个算式。它对应第 07 篇的路径边，只是多带了一个函数。

写成四元组 `〈d₁,n,d₂,j〉`：

- d₁：该过程入口的源事实。
- n：目标程序点，决定所属过程。
- d₂：目标事实。
- j：入口值到目标值的汇总函数。

对 calc，得到：

| 目标位置 | 跳转函数条目 | 含义 |
| :--- | :--- | :--- |
| 加法之后 | `〈p,n₁,a,t↦t+2〉` | 入口 p 到 a |
| 乘法之后 | `〈p,n₂,b,t↦5(t+2)〉` | 入口 p 到 b |
| 方法出口 | `〈p,exit,ret,t↦5(t+2)〉` | 入口 p 到返回值 |

出口处的汇总组成过程摘要。A、B 分别把 1、4 代入同一个摘要，就能保留各自的返回值。

## 6. 两阶段求解：先汇总函数，再代入值

经典 IDE 求解分两个阶段，算法见 [原论文全文](https://research.cs.wisc.edu/wpis/papers/tcs96b.pdf)。阶段一只传纸条不传数字，把每个位置的算式算好；阶段二从种子的初值出发，把数字代进算式。分开的原因在下面的例子里能看到：calc 内部若过早代入数字，p 就会变成 `1 ⊔ 4 = ⊤`，两个调用者再也分不开。

### 阶段一：传播与汇总函数

1. 在过程入口的同一事实上建立恒等跳转函数。
2. 遇到普通边，按执行顺序组合当前跳转函数和边函数。
3. 多条路径到同一条目时逐点合并；条目改变才继续调度。
4. 到达出口，生成或更新摘要，并应用到匹配的调用返回位置。
5. 与 IFDS 一样，处理“调用先到”和“摘要先到”两种时序，直到函数条目稳定。

在例子中，A 的实参产生函数是 `k₁`，B 的是 `k₄`：它们忽略输入、分别产生常量 1 和 4，对应调用流边 `Λ→p`。把它们与 calc 摘要 j 组合，调用者分别获得 `j∘k₁` 和 `j∘k₄`，即产生 15、30 的函数。

按[第 07 篇](07-ifds.md)的调度方式走一遍阶段一。条目写作 `〈源事实, 目标点, 目标事实, 函数〉`，`id` 是恒等函数，`n₁`、`n₂` 分别是加法、乘法之后的位置；调用者的两个接收变量写作 u、v。与第 07 篇一样，省略始终同行的 Λ 条目（calc 的 `〈Λ, entry, Λ, id〉`、调用者的 `〈Λ, retA, Λ, id〉` 等）：

| 步骤 | 当前任务 | 新条目 | 本次计算 / 后续动作 |
| :--- | :--- | :--- | :--- |
| 1 | 从种子出发 | `〈Λ, main入口, Λ, id〉` | 沿 main 的普通边到达 A |
| 2 | A 调用 `calc(1)` | 被调入口 `〈p, entry, p, id〉`；登记 Incoming(calc,p) ← A，附 `k₁` | 调度 calc 入口；旁路保留 Λ |
| 3 | `a=p+2` | `〈p, n₁, a, t↦t+2〉` | 组合 `id` 与边函数 |
| 4 | `b=a*5` | `〈p, n₂, b, t↦5(t+2)〉` | 组合上一条与 `t↦5t` |
| 5 | `return b` 到达出口 | `〈p, exit, ret, t↦5(t+2)〉`，记为摘要 j | 查 Incoming，把 j 应用到 A |
| 6 | 应用摘要到 A | `〈Λ, retA, u, j∘k₁〉`，即 `t↦15` | 继续 main，到达 B |
| 7 | B 调用 `calc(4)` | `〈p, entry, p, id〉` 已存在，不再传播；Incoming(calc,p) 追加 B，附 `k₄` | 摘要 j 已有，直接应用 |
| 8 | 应用摘要到 B | `〈Λ, retB, v, j∘k₄〉`，即 `t↦30` | main 到达出口，队列为空 |

第 7 步是 IDE 复用摘要的位置：calc 的方法体只分析了一次，B 拿到的是同一个 j，区别只在与它组合的实参函数。若第 5 步与第 7 步的顺序颠倒（B 的调用先于摘要到达），第 7 步就退化为登记等待，摘要产生后再补第 8 步；两种时序的最终条目相同。

### 阶段二：传播入口值并求值

从种子的初值出发，利用已稳定的调用关系与跳转函数求出过程入口值，再对所需条目求值。

| 查询 | 计算 | 结果 |
| :--- | :--- | :--- |
| A 返回后的 u | `j(k₁(★))` | 15 |
| B 返回后的 v | `j(k₄(★))` | 30 |
| calc 内部 p 的跨调用汇总 | `1 ⊔ 4` | `⊤` |

calc 内部位置跨调用汇总后得到未知，调用者却仍能通过各自的实参与摘要得到 15、30。提前把摘要压成“calc 返回未知”，就会丢掉这份输入输出关系。

## 7. 普通常量传播的分配性限制

第 05 篇的两条路径分别为 `(x,y)=(2,3)`、`(3,2)`。执行 `z=x+y`：

- 各自执行再合并：`5⊔5=5`。
- 先逐变量合并再执行：`⊤+⊤=⊤`。

结果不等，环境变换不满足分配律，因此不能直接套用前面的单事实值传播。calc 使用的是常量、复制和满足条件的一元线性变换；对两个变量联合求值时，需要重新检查模型。这就是原论文把示例限定为线性常量传播的原因。

## 本篇要点

- IDE 在 IFDS 的每条事实边上附加**边函数**：不传具体值，传“值怎么变”的算式。
- 顺序执行做**函数组合** `g∘f`（顺序不能颠倒），分支汇合做**逐点合并**；函数族必须对这两种操作封闭并能判等，这一条比值格有限高度更难满足。
- **跳转函数** `〈d₁,n,d₂,j〉` 是从方法入口到某位置的汇总算式，出口处的跳转函数就是方法摘要。
- **两阶段求解**：阶段一只传播算式，calc 只分析一次；阶段二代入实参，A、B 分别得到 15、30，而 calc 内部 p 的跨调用值是 `⊤`。过早代值就丢掉输入输出关系。
- 只涉及一个变量的常量、复制、一元线性变换满足分配律；`z=x+y` 这类两变量联合求值不满足，IDE 不能直接用。
