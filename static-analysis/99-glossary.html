                                                # 第 01 篇：状态、抽象与近似

                                                术语英文一句话解释在例子中
                                                具体状态concrete state某次真实执行在某个时刻的全部信息flag=true, x="alice", y="alice"
                                                抽象状态abstract state分析实际保存的、概括了一组具体状态的记号{x,y}：x、y 都可能有污点
                                                抽象域abstract domain分析允许写下的全部抽象状态的集合𝒫({x,y}) 的四个元素
                                                事实fact抽象状态中的一个原子条目x 表示“x 可能有污点”
                                                γ（具体化）concretization一个抽象状态所“放行”的全部具体状态γ({x}) 不含任何 y 有污点的状态
                                                转移函数transfer function一条语句怎样把执行前的抽象状态变成执行后的y=x：删旧 y，若含 x 则加 y
                                                控制流汇合control-flow merge / join point多条执行路线到达同一位置if 语句之后的 sink(y)
                                                过近似over-approximation结果覆盖全部真实行为，允许多算报告 y 可能有污点，即使某些路径上没有
                                                欠近似under-approximation结果只含真实行为，允许漏算只探索 flag=false 一条路径
                                                可靠sound在规定模型下结果覆盖真实行为，不漏报R ⊆ γ(S)
                                                精确度precision结果排除了多少不可能的情况{x} 比 {x,y} 精确
                                                误报 / 漏报false positive / false negative报告了不存在的问题 / 遗漏了真实问题用 {x,y} 进入 if(!flag) sink(y) 是误报
                                                路径敏感path-sensitive分析区分不同分支条件下的状态分别保存 (flag=true, {x,y}) 与 (flag=false, {x})
                                                may / mustmay / must analysis事实“可能成立”还是“所有路径都成立”可能有污点 / 保证已初始化

                                                中间表示IR, intermediate representation编译器或分析器内部使用的程序形式Jimple
                                                抽象语法树AST, abstract syntax tree按源码语法结构组织的树Clang 前端的输出
                                                Jimple—Soot 的有类型三地址中间表示y = x;、if flag == false goto n6;
                                                控制流图CFG, control-flow graph节点是语句或基本块，边是可能的执行转移n1…n7 与 n4→n5、n4→n6
                                                基本块basic block只能从块首进入、块末离开的连续语句B1=
                                                字节码bytecodeJVM 执行的指令序列aload_1; astore_2 对应 y=x
                                                三地址码three-address code将复杂表达式拆成简单操作，典型语句含一个运算、至多三个地址t = a + b；调用可有多个实参
                                                操作数栈operand stackJVM 暂存中间值的栈，字节码指令在其上取放数据input() 的返回值先在栈上，再 astore_1
                                                构建捕获build capture包裹构建命令、监控每次编译器调用以取得真实编译上下文Coverity 的 cov-build

                                                # 第 03 篇：数据流分析与格

                                                术语英文一句话解释在例子中
                                                IN / OUTin-set / out-set每个节点语句执行前 / 后的抽象状态IN[n6]={x,y}
                                                向前分析forward analysis信息沿执行方向从前驱流向后继污点从 input 流向 sink
                                                可达标记reachability flag区分“没执行到”与“执行到了但集合为空”入口可达且 IN=∅
                                                偏序partial order自反、反对称、传递的比较关系，允许有元素不可比本系列 a ⊑ b 表示 a 至少和 b 一样精确
                                                全序total order任意两个元素都可比较的偏序整数上的 ≤
                                                幂集power set, 𝒫一个集合的所有子集组成的集合𝒫({x,y}) 有四个元素
                                                上界upper bound位于两个元素上方或与之相等的元素{x,y} 是 {x}、{y} 的上界
                                                格lattice任意两元素都有最小上界和最大下界的偏序集𝒫({x,y})
                                                完全格complete lattice任意子集都有最小上界和最大下界的格；有限格自动满足𝒫({x,y})
                                                Join / 最小上界join, least upper bound, ⊔能同时容纳两边、又不多容的最小结果污点：并集；初始化保证：交集
                                                Meet / 最大下界meet, greatest lower bound, ⊓Join 的对偶污点：交集
                                                ⊤ / ⊥top / bottom格中最粗 / 最精确的元素污点域：{x,y} / ∅
                                                序对偶order duality把偏序整个反过来，Join 与 Meet 互换其他教材把并集叫 Meet 的原因

                                                # 第 04 篇：工作列表与不动点

                                                术语英文一句话解释在例子中
                                                工作列表worklist等待首次计算或重新计算的节点队列[Z,S]
                                                回边back edge从循环体末尾回到循环头的边C→H
                                                单调monotone输入按偏序变粗，输出不会变精y="safe" 的规则单调但会删事实
                                                不动点 / 最小不动点fixed point / least fixed point再算一遍也不变的状态 / 其中最精确的那个循环头稳定在 {x,y,z}
                                                上升链 / 有限高度ascending chain / finite height按偏序变粗的序列 / 严格上升的步数有统一上限{x} ⊑ {x,y} ⊑ {x,y,z}
                                                FIFO / LIFOfirst in, first out / last in, first out按加入顺序 / 逆加入顺序取出待处理节点H 依次加入 Z、S 后，FIFO 先取 Z，LIFO 先取 S
                                                优先队列priority queue按优先级选择下一个待处理节点固定优先级 H、Z、Y、C、S，让 S 晚些处理
                                                逆后序reverse postorder, RPO深度优先遍历完成节点的记录顺序反转；无环图上是拓扑顺序可用作向前分析的调度优先级
                                                轮询迭代round-robin iteration按固定顺序反复计算各节点，直到完整一轮无变化即使只有 H 变化，也会扫描一轮中的其他节点
                                                混沌迭代chaotic iteration每次选择一个分量，使用当前最新状态更新；需保证待更新项不被遗漏worklist 利用依赖关系安排这种迭代
                                                Kildall 算法Kildall's algorithm在格上合并并通过待处理集合传播变化的经典数据流算法首次到达或输入变化后继续处理后继
                                                区间域interval domain每个变量记一个 [下界, 上界]；数学整数上的区间域高度无限[0,2]
                                                加宽widening, ∇主动扩大结果以保证收敛；区间的一种做法是将向外移动的界推到无穷[0,1] ∇ [0,2] = [0,+∞)

                                                # 第 06 篇：调用关系与上下文

                                                术语英文一句话解释在例子中
                                                过程间分析interprocedural analysis跨过方法边界、处理调用与返回的分析追踪 a 经 id 到 b
                                                调用图call graph节点是方法，边是“可能调用”main→id
                                                过程间控制流图ICFG, interprocedural CFG把各方法的 CFG 用调用边、返回边缝在一起A→id 入口，id 出口→retA
                                                调用点 / 返回点call site / return site发出调用的位置 / 调用返回后继续执行的位置A / retA
                                                虚调用virtual call实际目标由接收者运行时类型决定的调用service.read()
                                                类层次分析CHA, class hierarchy analysis只按声明类型与子类关系确定调用目标service.read() 得到两个目标
                                                RTArapid type analysis在 CHA 基础上只保留程序中实际实例化的类去掉从未 new 的 NetReader
                                                基于指向的调用图points-to-based call graph先算变量指向哪些对象，再确定目标收缩为 FileReader.read
                                                上下文敏感context-sensitive区分同一方法在不同调用处的分析结果A 的返回不污染 B 的 c
                                                流敏感flow-sensitive区分语句顺序x=input(); x="safe"; 后 x 干净
                                                路径敏感（06 的例子）path-sensitive区分分支条件及其关联，定义见第 01 篇if (flag) … if (!flag) sink(y)
                                                调用到返回边 / 旁路call-to-return edge调用者中不经被调方法传播的事实所走的边执行 A 时 a 的污点直接保留
                                                摘要summary方法输入对输出影响的可复用记录id：入口 p 有污点则返回值有污点
                                                净化sanitizer按约定消除污点的操作escape(x)
                                                隐式流implicit flow值通过条件判断而非赋值影响另一变量if (x.equals("a")) y="a";

                                                # 第 07 篇：IFDS 事实传播

                                                术语英文一句话解释在例子中
                                                IFDSInterprocedural Finite Distributive Subset满足分配律的有限事实集合问题的过程间求解框架本系列的污点传播
                                                流函数flow functionIFDS 文献对转移函数的叫法y=x 的流函数
                                                分配律distributivity先合并再转移与分别转移再合并结果相同f(A∪B)=f(A)∪f(B)
                                                辅助事实 Λzero fact, Λ表示“无条件成立”的人为事实，用来生成新事实Λ→x 表示 x=input()
                                                表示关系representation relation一条语句的流函数拆成的单事实边集合y=x：x→x、x→y
                                                爆炸超图ESG, exploded supergraph节点是 (程序点, 事实)，边是单事实传播(A 之前, a) → (entry, p)
                                                四类流函数normal / call / return / call-to-return方法内 / 实参到形参 / 返回值到接收变量 / 旁路见第 07 篇第 3.3 节表
                                                路径边path edge“从方法入口带着 d₁ 进来，现在在 n 处是 d₂”〈p, exit, ret〉
                                                Incomingincoming等待某个被调入口事实结果的调用记录A 等待 (id, p)
                                                出口摘要 Summarysummary edge某入口事实能产生哪些出口事实；到达出口的路径边p→ret
                                                tabulation 算法tabulationIFDS 的求解算法，逐条登记路径边与摘要第 07 篇第 4.3 节伪代码
                                                可实现路径realizable path每次返回都回到匹配调用点的路径，允许有尚未返回的调用A 进 id 必须回到 retA
                                                MRP / MOPmeet over all realizable / all paths只沿可实现路径合并 / 沿所有路径合并IFDS 求的是 MRP，分配律成立时精确等于它
                                                CFL 可达性CFL-reachability路径上标签串须属于某个上下文无关语言调用返回的括号匹配

                                                可能别名may alias两个变量的指向集合有交集a、b 都含 o1
