                                            07｜IFDS：把集合传播拆成匹配路径上的事实传播

                                            读前须知

                                            需要第 03 篇的 Join、第 04 篇的单调与工作列表，以及第 06 篇的双调用例子。可分两次阅读：第 2—4 节学习单事实分解，第 5—7 节跟踪跨方法求解；第 8 节的 CFL 补充可选读。

                                            第 06 篇中的 id 用摘要 p→ret 服务两个调用。IFDS 将满足分配律的集合变换拆成单个事实的传播，最后收集到达同一位置的事实；求解时保留调用返回匹配，并复用摘要。

                                            # 1. 从集合变换到事实关系

                                            若事实域为 D={a,b,c,...}，可能的集合有 2^|D| 个；|D| 表示事实数量，每个事实有选或不选两种情况。逐一保存“某个输入集合经过方法得到什么集合”可能很昂贵。

                                            如果每个事实都能独立计算，再合并结果，就可以把方法效果表示成事实之间的关系。IFDS 的全称是 Interprocedural Finite Distributive Subset，对应过程间、有限事实域、分配性和事实子集。

                                            以下用 may 污点分析说明，路径合并取并集。must 类问题（交集合并）可以通过对事实集合取补集转成并集问题求解，本篇不展开。框架定义见 IFDS 原始论文open in new window。

                                            # 2. 分配律：先合并再转移，结果一样吗？

                                            **流函数（flow function）**是 IFDS 文献对转移函数的叫法，本篇沿用。**分配律（distributivity）**要求流函数 f 对任意 A、B 都有：

                                            f(A ∪ B) = f(A) ∪ f(B)

                                            即先合并再转移，与分别转移再合并，结果相同。这使逐事实计算能够恢复整份集合的结果。

                                            以 y=x 为例，x、y 是不同局部变量：

                                            输入 Sf(S)
                                            ∅∅
                                            {x}{x,y}
                                            {y}∅
                                            {z}{z}
                                            {x,y}{x,y}

                                            取 A={x}、B={y}，左边为 {x,y}，右边也是 {x,y}∪∅。一般地，删除旧 y 对每个输入事实独立生效，生成新 y 只依赖 x，因此这条规则对任意 A、B 都分配。

                                            一个反例是“只有同时包含 p、q 才新增 r”：

                                            g({p}) = {p}
g({q}) = {q}
g({p,q}) = {p,q,r}
g({p}) ∪ g({q}) = {p,q} ≠ g({p,q})

                                            这条规则需要两个事实联合触发，不能在原事实域上拆成独立单事实边。若重新设计复合事实域，需要重新验证有限性、语义与分配律。

                                            # 3. 用辅助事实表示无条件生成

                                            x=input() 在空集合上也会产生 x。为这种无条件生成引入辅助事实 Λ，读作 lambda：它沿可达路径传播，为新事实提供起点，不代表程序变量。

                                            对并集分配函数：

                                            f(S) = f(∅) ∪ 所有 d∈S 的 f({d}) 的并集

                                            因此可构造表示关系（representation relation）：

                                            • Λ→Λ：沿路径携带辅助事实。
                                            • Λ→d：表示 d∈f(∅)，即无条件生成。
                                            • d→d'：表示单事实 d 产生 d'，且 d' 不是无条件生成的；按定义，已由 Λ→d' 表达的结果不再画 d→d'。

                                            y=x 的边是 Λ→Λ、x→x、x→y 以及其他非 y 事实的恒等边。没有 y→y，因为旧 y 被覆盖。x=input() 则有 Λ→x 和辅助边，并保留其他变量事实；同样没有 x→x，旧 x 也被覆盖。

                                            # 4. ESG：展开程序点上的事实

                                            把程序点上的事实分别展开为节点，得到 ESG（Exploded Supergraph，爆炸超图）。节点 (n,d) 表示语句 n 执行前的事实 d，边由表示关系给出。“爆炸”指原来的 |N| 个程序点最多展开为 |N|×(|D|+1) 个节点。

                                            旧 y 被赋值覆盖，因此图中没有它的出边。这里仅展示 D={x,y}；其他未被修改的事实各有自己的恒等边。

                                            ESG 可以只按需要展开。某位置多个事实可达时，将它们收集起来就恢复了该处的事实集合。

                                            # 5. 调用中的四类流函数

                                            继续使用：

                                            static String id(String p) { return p; }
String a = input();
String b = id(a);       // A
String c = id("safe");  // B
sink(b);
sink(c);

                                            约定 id 无副作用，ret 表示抽象返回事实，各方法的局部变量事实带所属方法，避免同名混淆。

                                            类别本例的映射作用
                                            普通流来源 Λ→a；id 内 p→ret方法内部语句
                                            调用流A 的 a→p；B 仅传辅助事实实参映射到被调入口
                                            返回流A 的 ret→b；B 的 ret→c返回到相应接收变量
                                            调用到返回流（第 06 篇的“旁路”）保留调用者其他事实，删除接收变量旧事实表达不经被调局部状态传播的效果

                                            把这四类边放到程序点上，就得到本例的 ESG。图中省略了始终同行的 Λ 恒等边和未受影响事实的恒等边，只保留与污点有关的部分：

                                            查看可编辑图源open in new window

                                            左列依次是 A 之前、A 返回（同时为 B 之前）和 B 返回，右列是 id 的入口与出口。a 经 A 映射到 p，再由 ret 返回为 b；a 本身沿旁路保留。灰色虚线 ret→c 是 B 的返回流边，但 B 没有送入 p 的污点，因此 (retB,c) 没有匹配的到达路径。粗线 〈p,exit,ret〉 汇总 id 入口到出口的传播，称为路径边；本例只跨一步，一般可跨多步。到达出口的路径边构成摘要 p→ret。

                                            普通 BFS 会走通 (A 之前,a) → (entry,p) → (exit,ret) → (retB,c)，错误地污染 c。IFDS 必须排除这种不匹配返回。

                                            # 6. 走完一次摘要生成与应用

                                            求解器保存三类主要记录：

                                            • 路径边（path edge） 〈d₁,n,d₂〉：从当前方法入口事实 d₁，沿该方法内调用与返回已配平的路径，可到达 (n,d₂)。它可以跨越很多条程序边。
                                            • 入口记录 Incoming：哪些调用点、调用者路径边在等待某个被调入口事实的结果。
                                            • 出口摘要 Summary：某入口事实能够产生哪些出口事实。

                                            求解器推进路径边，到达出口后生成摘要，再按 Incoming 找到等待结果的调用者并回填。

                                            这种 Incoming 配合被调入口摘要的写法见 Naeem、Lhoták 与 Rodriguez 对 IFDS 的实用扩展open in new window，Heros 等实现采用它。原论文则将摘要记在调用点一侧，处理出口时扫描调用者路径边；两者结果相同。

                                            以下省略始终同行的辅助边，只追踪新增的污点关系；第一次进入 id 时也要分析 Λ 入口，以发现方法内部可能无条件产生的事实。本例 id 不产生新的来源。entry、exit 指 id 的入口与出口。

                                            步骤当前任务新记录后续动作
                                            1调用者执行 input〈Λ,A,a〉调度 A
                                            2A 调用 id(a)登记 A 等待 (id,p)；建立 〈p,entry,p〉调度 id 入口；旁路得到 〈Λ,retA,a〉
                                            3id 执行 return p〈p,exit,ret〉；摘要 p→ret查找等待该入口事实的调用
                                            4将摘要用于 A〈Λ,retA,b〉继续调用者，retA 处含 a、b
                                            5B 调用 id(safe)不产生入口 p 的污点；旁路得到 〈Λ,retB,a〉、〈Λ,retB,b〉Λ 摘要没有 ret 污点，故不生成 〈Λ,retB,c〉
                                            6到达两个 sinkb 有污点，c 没有队列为空，结束

                                            调用先到时，Incoming 记录等待关系，摘要生成后再回填；摘要先到时，新调用登记后立即应用它。求解器必须处理这两种时序，才能让结果不受队列顺序影响。

                                            # 7. 工作列表与摘要求解

                                            以下是正常控制流、静态目标、单出口模型下的 tabulation（制表）算法骨架——得名于它逐条登记路径边与摘要。propagate 只将未见过的路径边加入集合和工作列表。

                                            从种子建立 〈Λ, entryMain, Λ〉
while 工作列表非空:
    取出路径边 〈d1, n, d2〉
    if n 是调用点:
        按旁路流函数传播到返回位置
        for 每个调用目标 q、每个调用流结果 dq:
            登记 Incoming(q,dq) 中的调用点与调用者路径边
            propagate(〈dq, entry(q), dq〉)
            将已有 Summary(q,dq) 通过该调用的返回流应用到调用者
    else if n 是方法出口:
        将入口事实 d1 到出口事实 d2 的关系加入 Summary
        将新摘要应用到 Incoming 中所有对应调用
    else:
        沿普通边和流函数产生后继路径边

                                            应用摘要时，保留调用者原路径边的入口事实，再将被调出口事实通过返回流映射到接收变量，得到新的调用者路径边。多出口、异常以及库调用需要扩展对应的流函数和调度规则。

                                            # 递归如何停止？

                                            考虑概念方法 idRec(p,k)：k 为零时直接返回 p，否则递归调用 idRec(p,k-1) 并返回结果。污点域不追踪 k 的具体数值。

                                            1. 入口 p 沿直接返回分支产生摘要 p→ret。
                                            2. 递归调用登记等待同一 (idRec,p) 的结果，并复用这个摘要。
                                            3. 递归返回又得到 p→ret，但它已经存在，不再制造新任务。

                                            求解器反复加入新关系，直到得到闭包。有限的事实与程序点限制了关系数量，递归调用因而可以通过关系去重来处理。

                                            # 8. 精度保证与复杂度

                                            **可实现路径（realizable path）**要求每次返回都匹配调用点，允许有尚未返回的调用。在给定 ICFG、有限事实域和分配性流函数下，IFDS 精确求得这些路径的合并结果，称为 MRP（Meet over all Realizable Paths）。Meet 沿用文献的顺序约定，本篇实际取并集。

                                            不满足分配律时，直接拆成单事实传播可能漏算：第 2 节联合触发的 r 就会丢失。要继续使用 IFDS，需重新设计事实域，或构造满足分配律的保守近似并证明其覆盖关系。

                                            可实现只要求调用栈匹配，并不保证分支条件可满足。第 06 篇 flag 与 !flag 的例子仍会产生不可行的候选路径。

                                            **MOP（Meet over all Paths）**对图中所有路径合并，过程间裸图可能包含不匹配返回；MRP 排除这些路径。

                                            一般情形的时间界为 O(|E|·|D|³)：E 是 ICFG 的边集，D 是普通事实域，假定每条 ESG 边可在常数时间枚举。固定 E 时，事实数翻倍会使这个上界增长八倍；将访问路径、对象和条件编码进 D 会增加成本。特定问题可有更好的界，见原论文的复杂度分析open in new window。

                                            # 选读：用括号表示调用与返回

                                            将调用边标为左括号 (A，对应返回边标为右括号 )A，其他边标为空串。可实现路径要求每个右括号匹配最近的未配对左括号，允许留下未返回的调用；路径边则汇总两端配平的同层路径。

                                            判断图中是否存在标签串属于某个上下文无关语言的路径，叫 CFL 可达性（CFL-reachability）。IFDS 可视为 ESG 上的括号语言可达性问题，见 Reps 的综述open in new window。

                                            字段读写也可用另一类括号表示。若要求调用与字段两类括号各自精确匹配，一般问题不可判定，需要近似或限制模型；第 11 篇末尾的按需别名分析也面对这一问题。

                                            # 本篇要点

                                            • 分配律允许集合变换拆成单事实传播；无条件生成借助 Λ。直接拆分非分配性规则可能漏算。
                                            • ESG 展开程序点与事实，求解必须排除调用返回不匹配的路径。
                                            • 路径边、Incoming、Summary 支持摘要复用；两种到达时序都须处理，重复关系不再入队。
                                            • IFDS 精确求得给定问题的 MRP，但不保证分支条件可满足。一般时间界为 O(|E|·|D|³)。
